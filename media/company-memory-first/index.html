AIエージェントを作る前に会社の記憶を作った

社内の業務をAIに渡し始めて5日で、リポジトリのコミットは567件、記録した作業は105件になりました。速度は出ています。

ただ、最初の数日は出てくる提案をほとんど採用できませんでした。前日の会議でやめると決めた方向を持ってきたり、こちらが軽く指摘しただけで理由も聞かずに引っ込めたり。精度の問題ではなく、AIがこちらの文脈を持っていないことが原因でした。

この記事では、文脈をAIに持たせるために作った3つの仕組みと、途中で失敗した4つのことを書きます。100人規模で同じことをやる場合に何が変わるかも最後に整理しました。

課題に感じていたこと

最初の数日は、依頼のたびに背景を説明していました。この顧客とは前に何を決めたか。この価格にした理由は何だったか。誰が担当で、何をやらないと決めたか。新しく会話を始めるたびに同じことをもう一度書きます。

これは手間が増えるだけなので、まだ対処できます。問題は次の2つでした。

会議で決めたことをAIだけが知らない

会議で「その方向はやめよう」と話した翌日に、AIがその方向の提案を持ってきます。

こちらは議論を重ねて、やめた理由も温度感も共有できている。でもAIは、その議論が存在しない世界から答えます。だから出てくる案が、悪くはないけれど、今の話とは半歩ずれる。

問題は、ずれに毎回こちらが気づかなければいけないことです。提案を読んで、前提が古いと判断して、そこから説明し直す。この往復が提案のたびに発生します。

指摘するとすぐ引っ込める

「いや、そうじゃなくて」と軽く言うと、AIは反論せずに引っ込めます。こちらは思いつきで言っただけでも、さっきまでの案を取り下げて、こちらの言った方向に乗り換えます。

そうなると、最初の案が検討の結果なのか、こちらが喜びそうな方向に寄せただけなのかを判別できません。意見が一致しても、それが検討された意見かどうか確かめる手段がない。精度ではなく構造の問題です。

以下は、この2つをどう直したかの記録です。

やったこと

議事録をAIが必ず読む場所に置く

やったことはシンプルで、議事録を自動で取り込んで、AIが毎回読む場所に置きました。会議の音声から文字起こしを作り、決まったことと宿題を1ファイルに落とす。ここまでを自動にして、AIは作業を始める前に必ずそこを読みます。

会議が終わった時点でAIが内容を把握しているので、次に話しかけたときに説明がいりません。前提が古い提案も出なくなりました。

そのうえで想定していなかった変化があります。会議で出た宿題を、AIの方から「これ、こちらで巻き取りましょうか」と言ってくるようになりました。

議事録に宿題が書いてあり、AIはそれを読んでいて、自分にできるかどうかも判断できる。だったら手を挙げる、というだけの動作です。ただ、こちらが依頼を考えて言葉にする工程がまるごと消えるので、実際の効き方は大きい。

AI同士に直接やり取りさせる

社内でそれぞれ別の端末でAIを使っていると、記憶が端末ごとに割れます。

こちらで作った手順や、うまくいったやり方が、向こうのAIには存在しない。逆も同じで、向こうが持っている資料の作り方をこちらは知らない。同じ会社なのに、片方の端末だけが便利になっていきます。

これを人が橋渡ししようとすると、結局また人の手間になります。「あれ、向こうにも伝えといて」が増えるだけです。

そこで、お互いのAIが読み書きする場所を作りました。手紙箱と呼んでいます。こちらのAIが「そちらでやっている資料の作り方を、こちらでも再現できる形で置いてもらえますか」と書くと、向こうのAIが定期的にそこを見て、答えを書き戻す。人を経由しません。

人が関わったのは、最初に「ここを見に行ってください」と設定した一度だけです。いまはその箱の中でやり取りが続いていて、実際に資料作成の手順がこちらに渡ってきました。

批判役を別に立てる

すぐ納得する問題には、人格を分けて対処しました。

ひとつのAIに考えさせてそのまま出させると、どうしても甘くなります。自分の案を自分で叩けないし、こちらが少し押すと折れる。

まず、批判だけを担当するAIを別に立てました。提案を人に見せる前に、そこへ通します。提案を書いたAIには批判を書かせません。同じAIが両方やると、自分の案に都合のいい批判しか出てこないからです。

次に、別の会社のAIにも同じ問いを投げるようにしました。GeminiとCodexに、互いの回答を見せずに独立で答えさせる。そのあと、どちらが誰の回答か伏せたままお互いを批評させます。名前が見えていると遠慮が入るので、伏せます。

判断の扱いも決めました。3つの意見が揃ったら、人に確認を取らずに進めます。ひとつでも割れたら、結論が割れたのか、根拠が割れたのか、確信度が割れたのかを添えて人に上げます。

これで「すぐ納得する」が構造的に起きにくくなりました。ひとつが折れても、残りは折れません。

通すのは、価格をいくらにするかとか、どの事業に寄せるかといった、撤回コストの大きい判断だけです。料金がいくらか、その機能があるかといった、調べれば決着する問いには使いません。

うまくいかなかったこと

うまくいった話だけ書いても参考にならないので、詰まったところも書きます。

ルールを足しすぎました。ミスが出るたびに1行足していたら、3日で454行になり、そこから守られない率が上がりました。長くすると読まれる量が増えるだけで、効かなくなります。上限を400行と決めて、足すときは必ずひとつ消す運用にして戻しました。

社外に出すものを、承認なしで出しかけました。チャットへの投稿を、本文を見せないまま2回投稿してしまい、削除しています。いまは、送る前に本文を会話に出して明示のOKをもらう形にしました。取り消せる操作と取り消せない操作は、分けて考えないと事故ります。

AIの自己診断を信じすぎました。「ログインが切れています」と報告してきたので対応したら違った。翌日は「UIが変わったようです」と報告してきて、これも違った。どちらも同じバグでした。それ以来、同じ日の他の実行結果を先に見るようにしています。

同じ番号を、2つのAIが同時に取りました。別々に動いているセッションが、同じチケット番号を採番して衝突した。複数のAIが並行で書き込む前提の設計になっていませんでした。

人数が増えたときに変わること

いま試しているのは少人数の範囲です。100人規模で同じことをやるなら、変わる点が2つあると思っています。

ひとつは、文脈の入り口が分かれること。営業の最新は商談メモ、開発の最新はissue、経営の最新は会議にあります。全部を1箇所に集める必要はなくて、AIがそれぞれを読める状態にしたうえで、読んだ結果の解釈だけを1箇所に書き戻す。これが現実的なところだと思います。

もうひとつは、書き戻す人がいなくなること。少人数なら「気づいた人が直す」で回りますが、人数が増えると誰も直しません。善意に頼るのをやめて、作業手順の側に「終わったら該当ページを書き換える」を埋め込む。いまのところ、それしか思いついていません。

今日から始めるなら

定例会議をひとつ選んで、議事録の取り込みだけ自動にします。全部やろうとすると、たいてい途中で止まる。

決めたことを書いておきます。価格、担当、やらないと決めたこと。AIが一番よく聞いてくるのがここでした。組織図や業務フローは後回しで構いません。

批判役を別に立てます。これは今日からできて、提案を書かせたのとは別の会話を開き、提案文だけを貼って「反論して」と言う。それだけで通る案の質が変わります。

エージェントを作るのはこの後で十分だと思っています。文脈が揃っていない状態でAIを増やしても、説明する相手が増えるだけなので。

AI検索対策を伴走で進めるなら

社内の文脈をAIが読める形にすると、次に気になってくるのが、社外のAIが自社をどう説明しているかです。nitoは、AI検索での自社の見え方を実測しながら、記事とサイトの中身を直すところまで伴走しています。

nito の AI検索対策（LLMO / AEO）

nitoは、AI検索（LLMO／AIO）での見え方を計測するだけ・提案するだけで終わらせません。効く施策に絞って、記事の制作と改善まで実行します。まず無料診断で、いまの見え方を数字にします。

  • 本当に効く施策を、ピンポイントで：AI経由の問い合わせ・購入まで毎日追ってきたから、効く施策を切り分けられる
  • 提案で終わらせず、実行まで：記事の制作・既存記事の改善まで手を動かす
  • 主要AIでの見え方を毎日計測：ChatGPT・Geminiなどでの言及・引用を自社基盤で毎日計測し、次に直す場所を数字で決める

実際にあるSaaS企業では、AIでの言及率を10%から45%へ引き上げ、AI経由のコンバージョンを約4倍に改善しました。

よくある質問

Q. 議事録の取り込みは、どこまで自動にできますか

会議の録画から文字起こしを取り、決まったことと宿題をまとめて所定の場所に置くところまでは自動にできます。人の判断が要るのは、どれを決定として残すかの一点だけ。そこだけ目を通しています。

Q. 批判役のAIは、同じサービスの別会話でもいいですか

構いません。同じ会話の中で「批判して」と続けると、直前の自分の案に引きずられてしまう。会話を分けて、提案文だけを渡すと効きます。別の会社のAIも混ぜると、視点はもっと散るはずです。

Q. 複数のAIの意見が割れたときはどうしていますか

人が判断します。そのとき、結論が割れたのか、根拠が割れたのか、確信度が割れたのかを分けて出すようにしていて、根拠が割れている場合はたいてい前提の事実確認が抜けています。
