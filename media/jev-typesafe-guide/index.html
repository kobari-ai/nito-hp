【2026年9月】Jev（TypeSafe AI）とは？文章を書かないAIの仕組み・料金・使い方・苦手なこと

2026年9月15日、TypeSafe AIが「Jev」というAIモデルを公開しました。ChatGPTやClaudeのように文章を書くのではなく、渡された状況に対して「どれか」「どの段階か」「本当か」を確率つきで返すだけのモデルで、同社はこれを「System One モデル」と呼んでいます。公表値は応答70〜500ミリ秒、料金は入力100万トークンあたり$0.042で出力は無料です。

この記事は公式ドキュメント（2026年9月19日取得）を全ページ読んだうえで、仕組みと料金に加えて公式が認めている苦手なこと、LLMの出力を検査する使い方、日本語で使うときの注意まで含めて書きます。

この記事のポイント
  • Jevは文章を生成しない。Choice（どれか）・Score（どの段階か）・Noul（本当か）の3種類の答えを確率つきで返す
  • 料金は入力100万トークンあたり$0.042、出力は無料。1回に渡せるのは64,000トークンまで
  • 「ハルシネーションしない」の意味は用意した選択肢の外に答えが出ないこと。選択肢の中で間違えることはある
  • 得意なのはLLMの出力検査、問い合わせの振り分け、リード判定など判断を大量に繰り返す場面
  • 英語が主で、日本語を含むCJKは同等の精度が出ないと公式が明記。日付計算・数値・文章生成も苦手

Jevとは何か

JevはTypeSafe AIが「System One モデル」と呼ぶ新しい種類のAIです。LLMと同じように自然言語を読みますが、返すのは文章ではなく、型の決まった答えと確率です。公式ドキュメントの言い方では「state（状況）と型付きの質問を送ると、コードがそのまま使える構造化された答えが返る」モデルです。

System Oneの名前は、心理学者ダニエル・カーネマンの「速い思考（システム1）」と「遅い思考（システム2）」から取られています。TypeSafe AIの説明では、文章を組み立てながら答えるLLMを熟考型、一瞬で判断だけを下すJevを直感型として対比しています。開発者向けの説明では「賢いif文」という言い方もされています。

LLMと何が違うのか

LLMは答えを1トークンずつ順番に生成するため、100トークンの答えには100回の計算が要り、返答まで数秒かかります。Jevは渡された質問すべてに対する確率を1回の計算で並列に出す仕組み（公式は parallel sampler と呼んでいます）で、文章を作らない分だけ速く安くなります。

もう1つの違いは確率の意味です。公式ドキュメントによると、System Oneモデルは「較正された判断」のために訓練されており、返す確率は実際の結果に対して調整されています。ただし較正は予測の集団に対して測られるもので、個々の答えが正しいことを保証するものではないとも書かれています。

公開日と開発元

TypeSafe AIはOpenAI出身のDiogo Almeida氏らが率いる企業で、Jevは2026年9月15日に公開されました（heise onlineの報道と公式サイトのニュース）。現在の版は jev-1.13.0 で、公式ドキュメントには「AIモデルとして初めて公開されたSystem Oneモデル」とあります。

Jevに投げられる3種類の質問

Jevへの質問は「プリミティブ」と呼ばれ、3種類しかありません。質問ごとにIDと type と instructions（何を判断するか）を書き、ChoiceとScoreには criteria（選択肢や段階）を付けます。

質問の型 答えるもの 返る値 例
Choice どれか 選んだ1つ、全選択肢の確率、確信度 この問い合わせは請求・技術・営業のどの担当か
Score どの段階か 段階の期待値、段階ごとの確率、確信度 顧客の怒りは冷静・不満・激怒のどこか
Noul 本当か 0〜1の確率 この文面は返金を求めているか

公式ドキュメントの例では、決済連携が3日間失敗しているという問い合わせを渡して「担当」「怒りの度合い」「緊急か」の3問を同時に投げると、department: "billing"、frustration: 1.035、is_urgent: 0.999 のような答えが返ります。プログラム側は「緊急の確率が0.9を超えたら優先キューへ」「担当の確信度が0.6を下回ったら人が振り分ける」といった分岐をそのまま書けます。

質問の作り方の原則

公式ドキュメントが繰り返し書いているのは「1つの質問には1つの即断」という原則です。「このメッセージは緊急か」は良い質問で、「このメッセージを分析して最適な対応を決めて」は悪い質問です。複数の要因で決まる判断は要因ごとに別の質問にして、答えをコードで組み合わせます。スタートアップのピッチを採点したいなら「市場規模」「技術的な実現性」「チーム」を別々に聞く、という具合です。

料金と上限

公式の「Models」ページに載っている、2026年9月19日時点の仕様です。

項目 公表値
モデル jev-1.13.0（エイリアス jev-latest、jev-preview）
料金 入力100万トークンあたり$0.042。出力は無料
応答時間 70〜500ミリ秒（米国西海岸からの計測）
コンテキスト 1リクエスト64,000トークン。stateと最長の質問で32,000トークン
レート上限 毎秒250,000トークン・毎分1,200リクエスト（需要に応じて予告なく変動）
入力 テキストのみ。画像・音声・動画は非対応
学習への利用 顧客のリクエストと応答は学習に使わない。企業向けにゼロデータ保持あり

料金を業務の規模で見ると、問い合わせ1件を1,000トークンとして1件あたり$0.000042、1ドル150円なら約0.006円です。10万件を判定しても約630円で、出力が無料なので質問を増やしても入力分しか増えません。X上で共有されている「1決定あたり$0.0002」という数字は、ブラウザ操作のように1回のstateが数千トークンになる用途での実測値です。

Jevはファインチューニングもできません。同じ重みが全アカウントに使われ、自分の領域に合わせるのは質問文と選択肢の書き方、そして判断を小さな質問に分解してコードで組み合わせることで行います。

公式が挙げている使いどころ

公式の「Use case map」には14の領域が並んでいます。共通するのは判断を大量に、速く、決まった形で繰り返す場面だという点です。

  • カスタマーサポート: 問い合わせの分類、緊急度・不満・解約リスク・返金要求の検出、担当への振り分け、回答がポリシーに沿っているかの検査
  • 営業: 会社情報や受信メッセージを理想の顧客像と照合し、業界適合・成熟度・購買意図をスコアリングして優先順位を付ける
  • 採用: 履歴書や面接メモを職務要件と照合し、経験の関連性や必須スキルの根拠を採点して、担当者に振り分ける
  • コンテンツモデレーション: 有害・スパム・詐欺・個人情報の露出・ポリシー違反を検出し、深刻度と確信度で「通す・警告・確認・ブロック」を分ける
  • EC: 商品リストの分類と属性抽出、禁止商品や偽物・レビュー不正の検出
  • 保険・金融: 事故報告や取引記述からリスク指標を出し、専門家に回す案件を選ぶ
  • 法務・コンプライアンス: 契約や広告文を分類し、欠けている条項や禁止表現を検出する

LLMの出力を検査するVerifierとしての使い方

X上でも最も注目されている用途が、LLMの前後に置く検査役です。公式のクックブック「LLM guardrails」は、LLMの前に別のLLMを置く方法の問題を「毎ターン1回分の遅延と費用がかかり、攻撃者はそのLLMも言いくるめられる」と書き、代わりに1回のJevリクエストで検査する構成を示しています。

具体的には、1つのメッセージに対して「脱獄や指示の注入か」「危害や犯罪か」「診断や投薬量を含むか」「自傷か」といったNoulを並べ、さらに「従った場合の害の大きさ」をScoreで聞きます。「指示を無視しろ」という文は、指示として働く代わりに脱獄として採点されます。公式は入力と出力の両方に同じ検査をかけることを勧めています。普通に見える入力でも、有害な返答につながることがあるためです。

確信度でルーティングする

公式の「Confidence」ページには、確信度で処理を分けるコードの型があります。破壊的な操作ほど自動実行に必要な確信度を高く設定し、0.5を下回るものは「モデルが本当に迷っている」として必ず人に回す、という書き方です。しきい値は用途と自分のデータでの精度に依存するので、保守的な値から始めて、結果を見ながら調整するようにと書かれています。

公式が認めているJevの苦手なこと

公式ドキュメントには「Model jaggedness（モデルのむら）」というページがあり、jev-1.13が苦手なことが失敗の型ごとに整理されています。業務に組み込む前に見ておく表です。

苦手なこと 何が起きるか 公式の代替案
数値と計算 個数を数える、金額を比べる、Scoreの小数から正確な量を出す 数えるのも計算もコードで。モデルには「しきい値を超えるか」だけ聞く
数値の表現 16進のカラーコードやRGBより「赤」のような名前のほうが精度が高い コードで名前や区分に変換してから渡す
日付と時刻 どちらが先か、何日離れているか、期間内かの判定が不安定 日付の抽出だけモデルに任せ（月・日・年はChoice）、比較はコードで
回りくどい指示 二重否定や、性質の性質を問う多段の推論で精度が落ちる 直接的に書く。stateの該当箇所を名前で指す
無関係な情報の多いstate 判断に関係ない内容が増えるほど精度が落ちる コードで絞ってから渡す。無理ならNoulで関連性を先に判定
敵対的な内容 stateを「データ」として扱い、注入された指示を疑わない criteriaに明示する。多人数に出す前に十分テスト
指示とcriteriaの矛盾 trueが「いいえ」を意味するような書き方で混乱する criteriaを指示の延長として、同じ言葉で書く
質問形式をまたいだ一貫性 同じ問いをNoulとChoiceで聞くと数値が対応しない。「返金か」と「返金でないか」の確率の和が1にならない 聞きたいことをそのまま1つの形で聞く。しきい値を別の形式に流用しない
文章生成 Choiceを連鎖させて文章を作ることは技術的に可能だが、精度が低く遅い 生成は生成モデルに任せる

日本語で使うときの注意

公式の「Models」ページには、英語が主な学習言語で精度も英語が最も高く、日本語を含むCJKは扱えるが同等ではないので自分のコンテンツでテストしてから頼ること、と書かれています。日本語の問い合わせ分類に使うなら、まず数百件で英語と同じ精度が出るかを確かめ、確信度のしきい値を英語より保守的に置くのが現実的です。

日本から呼ぶ場合は通信の遅れも乗ります。公表の70〜500ミリ秒は米国西海岸からの計測なので、国内からだと0.5〜0.8秒程度になったという報告が日本の解説記事にあります。

使い始める手順

公式の「Quick start」に3つの入口があります。

  1. Playground: TypeSafeのコンソールにログインし、サンプルの文面を貼って質問を追加するだけで試せる。登録はウェイトリスト経由
  2. API・SDK: PythonとJavaScriptのSDKがあり、pip install typesafe-sdk のあと環境変数 TYPESAFE_API_KEY を設定して client.system_one(state=..., questions={...}) を呼ぶ。HTTPなら POST /v1/systemone
  3. コーディングエージェント用のスキル: Claude Codeなら claude plugin marketplace add typesafe-ai/skills と claude plugin install typesafe@typesafe-ai の2行でTypeSafeスキルが入り、「TypeSafeスキルを使って問い合わせを4分類するCLIを作って」のように頼める

AI検索の側から見たJev

「AI検索の回答が変わるのか」という質問をAI検索対策の相談で受けます。Jevは文章を生成しないので、ChatGPTやGoogleのAIモードのように回答を書く側には立ちません。変わりうるのは回答を出す前の検査と振り分けのほうです。AI検索を運営する側が「この引用元は信頼できるか」「この回答はポリシーに反しないか」を判定する層にJevのようなモデルを置けば、引用の選別が速く安くなります。自社サイトが引用されるかどうかの基準そのものは変わらず、判定の回数と速度が上がりうる、という見方です。実際に採用されるかは各社の実装次第で、公表されている事実はありません。

よくある質問

JevはChatGPTの代わりになりますか？

なりません。Jevは文章を書かず、選択・段階・確率だけを返します。文章を作る仕事はLLMに任せ、その前後の判断と検査をJevに任せる組み合わせが公式の想定です。

Jevは本当にハルシネーションしないのですか？

用意した選択肢の外の答えや、壊れた形式の出力は出ません。ただし選択肢の中で間違った答えを選ぶことはあり、公式も「較正は集団に対して測られ、個々の答えの正しさは保証しない」と書いています。

Jevは無料で使えますか？

料金は入力100万トークンあたり$0.042で、出力は無料です。無料枠の有無は公式ページに明記がなく、利用にはコンソールへの登録（ウェイトリスト）が必要です。

Jevは日本語に対応していますか？

日本語のテキストも受け付けますが、公式は英語が主で、CJKは同等の精度が出ないと明記しています。自分のデータでテストしてから使う前提です。

Jevはいつどこが出したモデルですか？

2026年9月15日に、OpenAI出身のDiogo Almeida氏らのTypeSafe AIが公開しました。現在の版はjev-1.13.0です。

Jevは画像や音声を判定できますか？

できません。入力はテキストだけで、画像・音声・動画は事前にテキストか構造化データに変換してから渡します。

Jevをファインチューニングできますか？

できません。同じ重みが全アカウントに使われ、自分の用途に合わせるのは質問文・選択肢の書き方と、判断の分解で行います。

JevとLLMのどちらを使えばいいですか？

答えが文章なら LLM、答えが「どれか・どの段階か・本当か」ならJevです。両方使うなら、LLMが作った文章をJevで検査してから外に出す構成が公式のクックブックにあります。
