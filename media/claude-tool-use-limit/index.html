【2026年10月】Claudeのこのターンのツール使用制限とは？続ける方法と出にくくする頼み方

Claudeに調べものやファイルの作業を頼むと、返答の途中で「Claude reached its tool-use limit for this turn」と出て止まることがあります。検索では「Claudeはこのターンのツール使用制限に達しました」という日本語で探されていますが、画面の文言として確かめられたのは英語の表示です。2026年3月13日にはClaude Desktopでツールの呼び出しが約20回で止まるようになったという報告がGitHubに投稿され、10月10日までに48件のコメントが付いています。

この表示は5時間や週間の使用量の枠とは別のものです。Anthropicのヘルプセンターにはこの表示を説明したページが無く（2026年10月10日に確認）、近い仕組みが書かれているのは開発者向けのAPIのドキュメントだけでした。この記事では公式の記述と、10月10日にウェブ版のClaudeで試した結果をもとに、表示の意味・続け方・出にくくする頼み方を整理します。どこまでが公式で、どこからが利用者の報告かは文ごとに分けて書きます。

この記事のポイント
  • 1回の返答（ターン）の中で使えるツールの回数の上限に当たったという表示。5時間・週間の使用量の枠とは別
  • ［続ける］か「続けて」で次のターンが始まる。止まる前の結果は会話に残るが、再開後に作業を取り違える報告もあるので結果を確かめる
  • アプリでの回数は公開されていない。報告は約20回（Claude Desktop、2026年3月）
  • 10月10日にOpus 5.5で試したときは表示は出ず、Claudeが自分で7道県分で区切って「続けて」を求めた
  • 出にくくするには、1通に詰め込まず対象と数を決めて分ける。使わないコネクタはオフにする

表示の意味と出る場所

ここでいうターンは送った1通のメッセージに対するClaudeの1回の返答です。会話全体や5時間の枠ではありません。1回の返答の中で、ウェブ検索・ページの読み込み・コードの実行・Googleドライブなどのコネクタの呼び出しを続けて行い、その回数が上限に達すると返答が一時停止します。

「ウェブで調べて」の一言でも、中では検索、ページの取得、読み込みが何回も走ります。調べる対象が多い頼みごとほど、1回の返答で呼び出す回数が増えます。

出る場所と、公式に書かれていることを並べると次のとおりです。

使う場所 止まり方 公式の記述
claude.ai（ウェブ・デスクトップアプリのチャット） この表示が出るという報告が多い ヘルプに説明なし
Claude Desktop＋MCPのツール 約20回で止まるという報告（GitHub） 同上

Claude CodeとAPIでの止まり方は、最後の節で扱います。スマホのClaudeアプリで同じ表示が出るかは、今回は試していません。後で触れるGitHubの報告のコメントには、iOSのアプリでは表示も［続ける］のボタンも出ないまま黙って止まったという声もあります。

公式に書かれていること

ヘルプセンターの「使用量と長さの制限はどのように機能しますか？」と「Claudeのエラーメッセージのトラブルシューティング」を10月10日に読み直しましたが、扱っているのは使用制限・長さ制限・容量制約などで、ターンごとのツールの上限には触れていません。

近い仕組みが書かれているのは、APIのドキュメント「停止理由とフォールバック」の pause_turn です。ウェブ検索などのサーバーツールを実行しているあいだに、サーバー側のループが反復回数の上限に達すると pause_turn が返り、既定の上限は1リクエストあたり10回の反復とされています。続けるときは返ってきた内容をそのまま送り返すよう案内しています。

後で触れるGitHubの報告の投稿者や海外の解説記事には、アプリの［続ける］をこの pause_turn と結び付けて説明しているものがあります。ただし、この10回はサーバー側の処理の反復の回数で、ツールの呼び出し回数ではありません。Anthropicも、アプリの表示がこの仕組みで出ているとは書いていません。アプリで何回まで使えるかは、公式には書かれていないと読むのが正確です。

何回で止まるのか

具体的な数字が出ているのはGitHubの報告です。2026年3月13日に「Per-Turn Tool Call Limit Regression Breaks Agentic MCP/SSH Workflows in Claude Desktop」が投稿され、以前は45分以上・60〜80回以上続けられた作業が、約20回で止まるようになったと書かれています。投稿者はMaxプランでした。

この報告はClaude Codeのリポジトリに出されたもので、投稿の直後に自動で invalid のラベルが付きました。10月10日の時点でコメントは48件ありますが、Anthropicの社員の返信は付いていません。

プランを上げると回数が増えるかどうかも、公式には書かれていません。Maxプランでも当たったという報告があるので、プランの変更で解決すると考えて上位プランに移るのは避けたほうが安全です。

ウェブ版で試した結果

2026年10月10日に、ウェブ版のClaude（Opus 5.5、思考の度合いは中）で、ツールをたくさん使う頼みごとを3回送りました。テーマは祝日と県庁所在地の人口で、結果は次のとおりです。

頼んだこと 結果
2026年の祝日16日を、1日ずつ別々に検索して一覧に 1回の返答で16日分が完了。表示は出なかった
47都道府県の県庁所在地を、1県ずつ検索して市の公式ページで人口を確かめる 北海道・東北の7道県で、Claudeが自分で区切って結果をまとめ、「続けて」と送るよう案内した
「続けて。残りは止まらずに沖縄県まで」と送る 茨城県の1県（検索3回とページの読み込み2回）で止め、会話の量が上限を超えるとして新しい会話で4〜5回に分けるよう勧めた

2回目の返答でClaudeは、1県あたり2〜4回の呼び出しが要り、ページの量も大きいので、最後まで続けると処理しきれなくなる可能性が高いと理由を書いていました。今回の3回ではツール使用制限の表示も［続ける］のボタンも出ず、その前にClaude自身が作業を区切りました。3回目に挙げた理由はツールの回数より会話の長さの上限に近いものです。長さの上限はClaudeの会話の長さ制限と圧縮で扱っています。

試したのは1つのアカウントとモデルで1日だけのため、表示が出なくなったとまでは言えません。

続けるで再開する手順

表示が出たときの手順は利用者の報告ではどれも同じです。10月10日の試用では表示が出なかったため、次の手順は利用者の報告をもとにしています。

  1. 表示の下にある［続ける］（英語の画面では Continue）を押す
  2. ボタンが無いときや押しても進まないときは、「続けて」とメッセージを送る
  3. 新しいターンが始まり、作業が再開する

止まる前の結果は会話に残ったまま再開できる、という報告が多い一方で、GitHubの報告には再開するとClaudeが何をしていたかを見失うことがある、残りのファイル操作を落としたまま終わったと答えた、という声も寄せられています。再開したら、止まる前に頼んだ作業が全部終わっているかを確かめてください。

使用量の扱いには気をつけてください。ヘルプの「使用制限のベストプラクティス」は、使用量に影響するものとしてウェブ検索などのツールの使用を挙げています。ツール使用制限そのものは使用量の枠と別でも、［続ける］で再開したあとの検索や読み込みは使用量に入ります。

出にくくする頼み方

1通に頼む量を減らせば、1回の返答で呼び出す回数も減ります。試した2回目でも、Claudeは7道県で区切ったうえで、新しい会話に表を貼って1回8〜10県ずつ頼むよう勧めていました。

  • 対象と数を先に決める。「全部調べて」ではなく「北海道・東北の7道県」のように区切る
  • 調べる段階とまとめる段階を分ける。検索とページの読み込みは回数を使い、表や文章にまとめる段階はほとんど使わない
  • 手元にあるデータは探させずに貼る。ファイルや表を渡せば、検索と読み込みの回数が要らない
  • 使わないコネクタとウェブ検索をオフにする

最後の項目はヘルプの「使用量と長さの制限はどのように機能しますか？」にも出てきます。ヘルプでは会話に要らないアプリを接続しているときはオフにし、最新の情報が要らないときはウェブを検索しないよう頼むことを挙げています。ただし、これはヘルプでは「コンテキストウィンドウのサイズを増やすには」の節の項目で、直後の注には「コンテキストウィンドウを最大化し、使用量制限を最適化する」とあります。ツールの回数の上限への対処として書かれたものではありません。

もう1つ、ヘルプの「使用制限のベストプラクティス」は、関連する質問を1つのメッセージにまとめるよう勧めています。ただ、検索の多い調べものは分けた方が、ツールの上限に当たりにくくなります。

使用量の上限との違い

「制限に達しました」と出たら、どの上限かを文言で見分けます。上限ごとに戻し方が違うためです。

ツール使用制限 使用量の枠 長さ制限
何の上限か 1回の返答の中のツールの回数 5時間・週間に使える量 1つの会話に入る量
表示の例 Claude reached its tool-use limit for this turn 5時間制限に達しました - [時刻]にリセット メッセージがこのチャットの長さ制限を超えます。
戻し方 続けるを押す・続けてと送る リセットを待つ・プランを上げる・使用クレジット 新しい会話にする
詳しい記事 この記事 Claudeの使用制限とリセット時間 Claudeの会話の長さ制限と圧縮

ツール使用制限に当たっても、使用量の枠が残っていれば待つ必要はありません。逆に、使用量の枠を使い切ったときは［続ける］では戻りません。ほかのエラーの文言はClaudeのエラーの原因と対処にまとめています。

Claude CodeとAPIで止まったとき

Claude CodeのCLIリファレンスでは、ターン数を制限する --max-turns はプリントモード（-p）だけのオプションで、既定では制限がないとされています。指定した回数に達するとエラーで終わるため、-p で動かしていて途中で止まるなら、まず --max-turns の値を見直します。Agent SDKでも、エージェントのループの max_turns に達すると error_max_turns が返ります。

APIでウェブ検索などのサーバーツールを使っていて stop_reason が pause_turn になったら、返ってきたアシスタントの内容を messages に足して、もう一度リクエストを送ります。ドキュメントは途中の server_tool_use の部分も含めて、そのまま送り返すよう求めています。自分で用意したツールで止まるときの停止理由は tool_use で、こちらはツールの結果を返して続けます。

よくある質問

Claudeのツール使用制限は何回までですか？

公式には書かれていません。数字が出ているのは利用者の報告で、Claude Desktopで約20回で止まったというものです（2026年3月）。

Claudeで続けるを押すと使用量に数えられますか？

ヘルプは使用量に影響するものにツールの使用を挙げています。［続ける］のあとの検索や読み込みもツールの使用なので、5時間・週間の枠を使います。ツール使用制限そのものは使用量の枠とは別の上限です。

Claudeのツール使用制限はプランを上げると増えますか？

公式には書かれていません。Maxプランでも約20回で止まったという報告があるため、回数を増やす目的で上位プランに移る根拠はありません。

Claudeで続けるを押しても進まないときは？

「続けて」とメッセージを送ると新しいターンが始まります。それでも同じところで止まるなら、頼みごとを対象と数で区切って送り直します。会話が長くなっているなら、結果を貼って新しい会話で続けます。

Claude Codeでもツール使用制限は出ますか？

ターン数を決める --max-turns はプリントモード（-p）だけのオプションで、指定しなければ制限はありません。指定した回数に達するとエラーで終わります。

ClaudeのAPIでpause_turnが返ったときは？

返ってきたアシスタントの内容をそのまま messages に足して、もう一度リクエストを送ります。最初からやり直す必要はありません。

Claudeのツール使用制限はいつリセットされますか？

公式の説明はありません。GitHubの報告では1ターンに約20回と数えていて、［続ける］のたびに次のターンとして数え直していると読めます。時刻を待つ必要はなく、［続ける］を押すか次のメッセージを送れば新しいターンが始まります。
